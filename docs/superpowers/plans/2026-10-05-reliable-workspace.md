# 2.7.0 实施计划

**Goal:** 实现并验收已授权的四项优化，发布 2.7.0。
**Architecture:** 工作区由 Electron 固定路径保存并验证授权，任务由 Python 保存检查点，预览使用独立 PythonBridge。前后端只通过窄 IPC / RPC 接口传递有界数据。
**Tech Stack:** Electron / Vue / TypeScript / Python / PyMuPDF。
**Spec:** ../specs/2026-10-05-reliable-workspace.md

## Global Constraints

保持 3000 来源、100000 页、只读原文件、不覆盖已有输出；缩略图有界；不持久化授权令牌。使用现有环境，不增加无必要依赖。任务执行已获用户明确授权。

## Review Focus

恢复后文件被替换；连续保存乱序与写入失败；暂停后取消或退出；检查点输出丢失或变化；磁盘不足与中途失败后的重复输出。各负责单元必须覆盖对应测试。

## 工作单元

- [x] 工作区：新增固定存储模块、类型及自动保存恢复组合函数；更新 PDF 工作台、扫描复核、来源导航。测试保存/恢复/重定位/规模。
- [x] 任务后台：任务持久化、暂停继续与重试参数接口、输出检查点；测试排队与运行状态、中断恢复及数据校验。
- [x] 输出资源：分来源/分卷输出、空间检查、单元检查点、完成输出验证；测试正确页序、失败重试、OCR TXT 部分失败与不足空间。
- [x] 主进程与任务中心：窄 IPC、恢复授权、独立预览进程、任务界面与关闭刷新；测试越权、进程故障、真实界面流程。
- [x] 发布：全量回归、3000 份真实桌面场景、冻结引擎与包运行、隔离安装升级验证、版本/日志/产物核验、提交推送并发布。

每个单元先运行新增测试确认缺失行为，再实现并运行针对性回归；集成后全量检查。可独立的前三个单元按并行技能拆分明确文件所有权，主代理负责主进程、共享接口集成与最终发布。

最终结果：v2.7.0 已发布。267 项单元/集成测试、40 项桌面检查、13 项冻结引擎检查及 3000 份规模场景通过。实际安装升级、旧版检查与下载公开新版本通过；GitHub runner 计费锁定改用有保护的本机临时目录测试，测试安装已卸载。详见 `docs/release-2.7.0.md`。
