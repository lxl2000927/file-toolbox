# 2.7.0 大批量工作区与长任务可靠性

用户已授权全部实现上一轮四项优化、测试并发布。版本按新增能力提升至 2.7.0，继承 v2.6.0 五项附件与中文更新日志格式。

## 目标与边界

- 3000 份文件、100000 页的整理进度可自动保存并在重启后恢复；保存来源、签名、页序、旋转、设置和扫描人工复核状态，不复制源文件或保存缩略图。
- 变更、缺失来源明确展示，支持重新定位内容相同的文件；不得把保存的任意路径直接作为新授权，源签名与主进程记录的身份需要验证。
- 后台任务集中呈现状态与进度，支持取消、合作式暂停/继续；重启后未完成任务标为中断，用户主动续做。保留完成文件并仅重试未完成单元。暂停发生在安全处理边界，不承诺中断一次原生 OCR 调用。
- 工作台提供来源搜索/分组、跳转至来源页及工作区页码、错误来源筛选，维持有界缩略图数量。
- 输出支持原有单文件、按来源与按页数分卷。检查可用磁盘与输出资源预算；完整大合并仍会随最终文档增长，界面必须如实说明并提供分卷。
- 预览使用独立长期存活 Python 进程，禁止借多线程同时进入 MuPDF 来提速；进程退出与取消按所属进程路由。

## 组成

1. 主进程固定位置原子工作区存储与授权恢复；前端自动保存、缺失定位和来源导航。
2. 后端固定位置任务日志、生命周期与完成单元检查点；主进程重試时从存储读取参数并重新校验授权，渲染器不能注入恢复记录。
3. PDF 输出资源策略、单元进度与检查点，只有完整原子输出才可标记完成；检查点损坏或输出变化不能静默跳过。
4. 统一任务中心、独立预览桥接与打包升级验证。

## 验收

先补失败回归，再实现。覆盖原子保存失败/旧请求覆盖、保存后立即关闭、3000 份恢复、源缺失/替换/重定位、队列暂停取消、运行暂停继续、引擎异常与重启恢复、失败单元重试不重复已完成输出、磁盘不足/分卷顺序、重任务期间预览与进程清理。完整 Python/Node/类型/构建/真实桌面/规模回归后，构建独立引擎和三种分发，核验更新元数据、哈希与版本。安装/升级通过隔离目录与用户数据验证，避免改动用户现有安装；如环境不具备完整隔离能力，明确记录限制，不伪称通过。
