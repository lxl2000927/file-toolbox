# v2.7.1 修复核验

以 `fc568486152651506329caba323451a35a31f888` 为基线，修复 2.7.0 审查确认的 11 项问题、两项性能问题及恢复/资源边界。此次用户授权修复、打包和提交，产物在本地生成，不创建新的公开 Release。

## 修复范围

- 撤销：验证本次产物的文件身份和内容，拒绝删除或移回已被外部编辑、替换的文件；保留失败操作供重试。
- 工作区：首次恢复失败不解锁编辑、不虚假确认已保存，可重试恢复；保留未读磁盘数据。
- 页面操作：筛选后的 Shift 和全选只选可见页；全工作区批量选页会解除筛选，展示全部选择。删除缺失来源页后，输出与空白检查只传入实际引用的来源，撤销仍可恢复原状态。
- 来源恢复：清空后重置错误和筛选；扫描重新定位按当前角色/路径计算索引；原生同路径重选可刷新空签名身份，普通编辑不会重复计算文件散列。
- 主进程：在核对原文件身份后迁移重命名授权；崩溃页面关闭时排空已接受的主进程写入；续做沿用已核验的原输出目录身份。
- 任务：普通拆分完整发布后先提交检查点再响应暂停，避免重复续做；按合并后状态限制任务记录容量并兼容旧日志；容量不足时仍可记录终结状态，使用有限恢复额度保留已经发布的文件路径；扫描检查点页数与实际文件核对。计数上限保持优先清理已完成记录、最后清理最旧终态记录，运行中记录不淘汰。
- 资源：所有普通/扫描输出写入路径检查磁盘空间；多帧图片解码前检查尺寸与内存，并逐帧响应取消。
- 性能：稀疏选页仅复制选中范围，重建有效链接，保留表单、书签、重复页及旋转；检查点按单元更新，兼容 v1 和原有完整快照回调。

## 行为边界

- 多帧图片仍以完整来源文档转换，但在分配前执行保守预算。超过预算的图片需要先缩小或拆分，输出分卷不能降低来源导入成本。
- 暂停/取消在安全处理边界响应，原生 OCR 调用需要先结束。
- 崩溃关闭只能等待主进程已接收的写入，不能恢复已经随渲染进程丢失的内存。
- 任务记录仍有容量上限。旧超容量记录可以读取、核验并复用已有检查点，新增数据继续超限时会明确拒绝；过长错误详情可能截短，已有检查点和终结时记录的输出路径保留。
- 文件包未配置代码签名证书。安装测试使用前置检查、唯一目录和独立配置，结束后卸载测试副本。
- 上次核验发现 GitHub Actions 受账户计费锁定影响；本次使用本机隔离验收，没有把未执行的 CI 记为通过。

原始验收证据保存在 Git 忽略的 `acceptance-samples/release-2.7.1/` 及各桌面验收目录。
